# SIGNAL

Full-stack рабочее пространство для командного сбора freelance-объявлений. Интерфейс на русском, desktop-first: чёрная навигация, светлая сетка, лаймовые акценты. Next.js 16 / React 19, Node.js 22, PostgreSQL 16, отдельные worker и scheduler, очередь задач в PostgreSQL. AI и клиентских заглушек данных нет.

## Быстрый запуск в Docker

1. Скопируйте `.env.example` в `.env`.
2. Задайте `OWNER_EMAIL`, `OWNER_PASSWORD` (минимум 12 символов) и `ENCRYPTION_KEY` (случайная строка минимум 32 символа). Для ключа: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
3. Выполните `docker compose up --build -d`.
4. Откройте http://localhost:3000 и войдите как владелец.
5. Нажмите «Обновить источники». Mock Studio заполнит базу девятью явно демонстрационными объявлениями, включая одну пару возможных дублей.

Миграция и bootstrap выполняются сервисом `migrate` до старта web/worker/scheduler. База хранится в Docker volume. `.env` не коммитить. Демонстрационного входа без авторизации нет. Для APP_URL на http://localhost cookie Secure отключён; на HTTPS Render он включён.

## Render

Загрузите содержимое проекта в Git-репозиторий и создайте **Blueprint** из `render.yaml`.

Blueprint создаёт четыре ресурса: web, background worker, отдельный постоянно работающий scheduler и PostgreSQL. Используются платные планы. Точная стоимость определяется Render при создании. Redis не требуется: очередь хранится в PostgreSQL, отдельные процессы забирают задачи через `FOR UPDATE SKIP LOCKED`.

При создании задайте:

- `APP_URL`: итоговый HTTPS-адрес web-сервиса без завершающего `/` (например, адрес, показанный Render). При отличии адреса измените переменную до входа. Она используется для проверки Origin и ссылок приглашений.
- `OWNER_EMAIL`, `OWNER_PASSWORD`: первый владелец создаётся только серверной командой bootstrap.
- `ENCRYPTION_KEY`: Render генерирует ключ и передаёт один и тот же web и worker. Сохраните его резервную копию; замена без перешифрования делает старые токены нечитаемыми.
- `CONNECTOR_ALLOWED_HOSTS`: список согласованных с площадками доменов через запятую. Для загрузки RSS/API он нужен **worker**. Заполните согласованно и в web для дальнейшего расширения.

Web выполняет `node server/setup.mjs --bootstrap` перед запуском. Worker/scheduler при первоначальном ожидании базы повторяют попытку; первая миграция сериализована advisory lock. Bootstrap идемпотентен по email: после успешного создания владельца удалите `OWNER_PASSWORD` из Render и замените pre-deploy command на `node server/setup.mjs`. Не меняйте email bootstrap для обычного обновления — это намеренно создаёт отдельную команду.

Проверка готовности: `GET /api/health` проверяет доступность PostgreSQL. Для проверки worker смотрите время последней синхронизации и статус источника. Убедитесь, что после первого обновления появились 9 mock-объявлений, повторное обновление не увеличивает их число, а в «Возможных дублях» появилась одна пара.

Справочник Blueprint: https://render.com/docs/blueprint-spec

## Рабочие функции

- Лента: поиск по названию, описанию и навыкам; источник, минимальная оценка, сортировка по дате/оценке/валюте и бюджету, пагинация; личное избранное и командный архив.
- Воронки: создание нескольких досок, добавление/переименование/порядок этапов, drag-and-drop карточек; альтернативное перемещение через селектор в карточке с клавиатуры. Карточка относится к одному этапу одной воронки.
- Карточка: назначение участника, приоритет, заметки, история, исходные поля, ссылка, объяснение оценки. Изменения проходят через API.
- Источники: индивидуальные подключения, зашифрованные секреты, владелец, интервал 10–30 минут, ручной запуск, отключение, последнее обновление, число полученных и новых записей, ошибки и статус задачи.
- Команда: приглашения на 72 часа, одноразовое принятие с совпадением email, четыре роли, изменение ролей владельцем. Приглашения копируются вручную; почтовая отправка не подключена.
- Оценка: настраиваемые детерминированные правила, положительные/отрицательные баллы, исключающие признаки, немедленный пересчёт всей команды. Итог ограничен 0–100. Пропущенные данные не совпадают с правилами. Валютное сравнение бюджета действует только в указанной валюте, конвертации нет.
- Дубли: уникальность `(team_id, platform, external_id)`. Повторное получение обновляет исходные поля и оценку, сохраняя этап, приоритет, ответственного, архив, заметки и избранное. Возможные дубли по сходству токенов названия ≥75% показываются парами. Подтверждение связывает две версии, но не удаляет и не объединяет их содержимое. Поиск кандидатов ограничен 2000 последними записями команды.

## Синхронизация и восстановление

Scheduler проверяет сроки раз в 15 секунд. У каждого подключения интервал 10–30 минут. Через минуту после создания сессии backend проверяет сроки; browser отправляет дополнительный идемпотентный запрос. Даже без открытой вкладки работает серверный scheduler.

Частичный уникальный индекс разрешает только одну queued/running задачу на подключение. Worker атомарно резервирует задачу с lease 2 минуты, выполняет коннектор с лимитом 30 секунд и сохраняет результат в транзакции. Упавшие задачи повторяются с задержками 2/4/8 минут до четырёх попыток; просроченные lease восстанавливает scheduler. После исчерпания попыток следующий обычный интервал позволяет новую задачу. Отключение перед сохранением проверяется повторно. Завершённые задачи удаляются через 30 дней. Несколько экземпляров scheduler/worker поддерживаются PostgreSQL-блокировками.

## Коннекторы

- **Mock Studio** — реалистичные, явно маркированные демонстрационные данные, реальные API и SQL-путь сохранения.
- **RSS / Atom** — HTTPS-лента с реальными полями; неизвестные бюджет, навыки, клиент остаются пустыми.
- **JSON API** — разрешённый HTTPS endpoint, возвращающий массив единой модели (см. `modules/README.md`).
- **Серверный модуль** — доверенный `.mjs` файл, установленный оператором через репозиторий. Администратор регистрирует его в UI. Это доверенный код с привилегиями сервера, не песочница. Проверяйте модуль до установки.

Готовых интеграций Upwork, Fiverr и других закрытых API в проекте нет: для них нужны разрешения и отдельное отображение схемы данных. Их подключённое состояние не имитируется. CAPTCHA и ограничения не обходятся. HTTP helper ограничивает домены, отклоняет редиректы и приватные IPv4-адреса, фиксирует результат DNS, ограничивает ответ 2 МБ и ожидание 20 сек. При 401/403/429 показывается ошибка, автоматических обходов нет.

## Разработка

Node.js ≥22.13. Установите зависимости `npm ci`, задайте переменные окружения и подключите PostgreSQL.

```sh
npm run db:bootstrap
npm run dev
```

В двух отдельных терминалах:

```sh
npm run worker
npm run scheduler
```

Для локальной загрузки `.env` в Node CLI используйте `node --env-file=.env server/setup.mjs --bootstrap`, аналогично для worker/scheduler; Next автоматически читает `.env`.

```sh
npm run build
npm test
```

`tests/signal.test.mjs` проверяет реальную PostgreSQL-схему и API на PGlite (PostgreSQL WASM), без подмены SQL результатами. В тестах адаптирован только transport пула. Это не заменяет нагрузочное тестирование многопроцессной очереди на внешнем PostgreSQL.

## Ограничения проверки и эксплуатации

Production-сборка Next.js и 13 автоматических проверок API, PostgreSQL-схемы и безопасности успешно пройдены в среде разработки. Развёртывание Docker/Render и браузерное end-to-end тестирование в этой поставке не выполнялись; адрес развёрнутого сервиса отсутствует. После публикации выполните smoke-проверки из раздела Render. Настройте резервные копии PostgreSQL и ключа шифрования. Почтовой доставки, password reset и готовых закрытых marketplace-интеграций нет. Восстановление пароля — операция доверенного администратора базы с использованием `hashPassword` из `server/security.mjs`.

Изоляция реализована серверным team scope во всех API и составными foreign key; database role принадлежит приложению и видит все команды, RLS не используется. SQL всегда параметризован. Сессии HttpOnly/SameSite=Lax, 7 дней; пароли scrypt, секреты AES-256-GCM; приглашения и сессионные токены хранятся как SHA-256 digest. Политика Origin ограничивает мутации; на production cookie Secure. Вход ограничен 20 попытками на email за 15 минут. Этот лимит не заменяет внешний сетевой rate limit для публичной эксплуатации.
